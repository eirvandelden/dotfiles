# Plan: Neovim shows an error on every launch

From `intent.md` (2026-10-08). Status: accepted.

## Context

The `neovim` stow package holds a standalone lazy.nvim config. `~/.config/nvim` is a symlink to `~/Developer/dotfiles/neovim/.config/nvim` in the main checkout. `lua/config/lazy.lua` sets `defaults.version = false` and runs `require("lazy").update({ show = false })` on `User VeryLazy`, so every launch moves every plugin to its newest commit.

avante.nvim commit `4f49656` (2026-10-06) requires `mega.cmdparse` at load time: `plugin/avante.lua:142` and `lua/avante/commands.lua:156` call `require("mega.cmdparse")`. The upstream README declares it as `{ "ColinKennedy/mega.cmdparse", dependencies = { "ColinKennedy/mega.logging" } }`. `neovim/.config/nvim/lua/plugins/ai.lua` does not declare either plugin. Sourcing `plugin/avante.lua` then fails at line 142, so `:Avante`, `:AvanteSwitchProvider` and the other commands defined after that line do not exist.

Research for this plan reproduced the failure and the fix in an isolated headless Neovim (NVIM v0.12.5):

- Unchanged config: one error notification, `Failed to source .../avante.nvim/plugin/avante.lua`; `exists(":Avante")` is `0`; `require("mega.cmdparse")` fails.
- Config with the two plugins added: no error notification and no error message; `exists(":Avante")` is `2`; `:Avante --help` prints the usage at info level; a bare `:Avante` prints the same usage at error level; `;aa` opens windows with filetypes `Avante`, `AvanteSelectedFiles` and `AvanteInput`.
- `;aa` opens the ask prompt in the unchanged config too: avante's `setup()` still runs and maps it. The red signals are the startup error and the missing `:Avante` command.
- No other plugin produced an error at startup in that run.

## Design decisions

- Declare the two plugins inside avante's `dependencies` list, in the upstream README's form: `{ "ColinKennedy/mega.cmdparse", dependencies = { "ColinKennedy/mega.logging" } }`. They exist only for avante, so they belong in avante's spec. lazy.nvim loads them before avante; no `lazy`, `event` or `version` keys are needed.
- No version pins. The intent keeps auto-update on every launch, and the config's `defaults.version = false` applies to the new plugins too.
- Do not use lazy.nvim's luarocks route. avante's `avante.nvim-scm-1.rockspec` lists `mega.cmdparse`, so lazy.nvim derives `build = "rockspec"` for avante. The config's own `build = "make"` overrides it, so lazy.nvim never calls luarocks. luarocks is not installed, and installing it is a system change that the intent does not approve.
- The committed test is a static Ruby test in `test/`, like the other repository tests. CI (`.github/workflows/dotfiles-tests.yml`, ubuntu-latest) has no Neovim. Installing it needs a workflow change, which rule 13 does not allow without approval. A test that skips when Neovim is missing breaks the no-skipped-tests rule. So the behaviour proof is a headless startup probe that the implementer runs locally and records as evidence. Its source is in this plan, under "Startup probe".
- "`:Avante` runs" is checked literally: the probe runs a bare `:Avante` and expects upstream's usage text, `Usage: Avante {acp,rag} [--help]`. Upstream reports that text at error level, by design, so the probe runs it last, after the error checks. `:Avante --help` is a second check; it prints the same usage at info level.
- `lazy-lock.json` comes from a real lazy.nvim run against this worktree's config. No hash is typed by hand.

### Startup probe

Save as `probe.lua` in your scratchpad. It needs two environment variables: `PROBE_OUT` (the result file) and `PROBE_FILE` (a file to open before `;aa`). This exact script passed against a config with the fix and failed against the unchanged config during planning.

```lua
-- Headless startup probe: fire VeryLazy, wait for lazy.nvim, check errors and avante's entry points.
-- Writes one line per check to $PROBE_OUT and ends with RESULT pass or RESULT fail.
-- The exit status says nothing: a plugin exit hook resets it, so the caller greps for RESULT pass.
local out = assert(os.getenv("PROBE_OUT"), "PROBE_OUT unset")
local probe_file = assert(os.getenv("PROBE_FILE"), "PROBE_FILE unset")
local lines = {}
local failures = 0

local function check(passed, line)
  if not passed then
    failures = failures + 1
  end
  table.insert(lines, (passed and "OK " or "FAIL ") .. line)
end

local function busy()
  for _, plugin in pairs(require("lazy.core.config").plugins) do
    for _, task in ipairs(plugin._.tasks or {}) do
      if task:running() then
        return true
      end
    end
  end
  return false
end

local function error_notifications()
  local messages = {}
  for _, notif in ipairs(Snacks.notifier.get_history({})) do
    if notif.level == "error" then
      table.insert(messages, (notif.msg:gsub("\n", " | ")))
    end
  end
  return messages
end

local function error_messages()
  local messages = {}
  for line in vim.api.nvim_exec2("messages", { output = true }).output:gmatch("[^\n]+") do
    if line:match("^E%d+:") or line:match("[Ee]rror") then
      table.insert(messages, line)
    end
  end
  return messages
end

local function usage_count()
  local count = 0
  for _, notif in ipairs(Snacks.notifier.get_history({})) do
    if notif.msg:match("^Usage: Avante") then
      count = count + 1
    end
  end
  return count
end

local function runs_with_usage(command)
  local before = usage_count()
  local ok = pcall(vim.cmd, command)
  return ok and vim.wait(2000, function() return usage_count() > before end, 50)
end

local function window_filetypes()
  local filetypes = {}
  for _, win in ipairs(vim.api.nvim_list_wins()) do
    table.insert(filetypes, vim.bo[vim.api.nvim_win_get_buf(win)].filetype)
  end
  return filetypes
end

-- Headless Neovim never fires UIEnter, so lazy.nvim never fires VeryLazy by itself.
vim.api.nvim_exec_autocmds("User", { pattern = "VeryLazy", modeline = false })
vim.wait(1000, function() return false end)
check(vim.wait(600000, function() return not busy() end, 200), "LAZY_TASKS_FINISHED")
vim.wait(3000, function() return false end)

for _, message in ipairs(error_notifications()) do
  check(false, "STARTUP_ERROR " .. message)
end
for _, message in ipairs(error_messages()) do
  check(false, "STARTUP_MESSAGE " .. message)
end

check(vim.fn.exists(":Avante") == 2, "AVANTE_COMMAND_DEFINED")
check(runs_with_usage("Avante --help"), "AVANTE_HELP_PRINTS_USAGE")

vim.cmd("edit " .. vim.fn.fnameescape(probe_file))
vim.api.nvim_feedkeys(vim.keycode("<leader>aa"), "mx", false)
check(
  vim.wait(5000, function() return vim.tbl_contains(window_filetypes(), "AvanteInput") end, 100),
  "ASK_PROMPT_OPENS " .. table.concat(window_filetypes(), ",")
)
for _, message in ipairs(error_notifications()) do
  check(false, "AFTER_ERROR " .. message)
end

-- Last on purpose: upstream reports a bare :Avante's usage text at error level.
check(runs_with_usage("Avante"), "AVANTE_BARE_PRINTS_USAGE")

table.insert(lines, failures == 0 and "RESULT pass" or "RESULT fail")
vim.fn.writefile(lines, out)
vim.cmd("qa!")
```

The probe passes only when its last line is `RESULT pass`. Every check writes an `OK` or a `FAIL` line: `LAZY_TASKS_FINISHED`, one `FAIL STARTUP_ERROR` or `FAIL STARTUP_MESSAGE` line per error, `AVANTE_COMMAND_DEFINED`, `AVANTE_HELP_PRINTS_USAGE`, `ASK_PROMPT_OPENS` (with the window filetypes), one `FAIL AFTER_ERROR` line per error after `;aa`, and `AVANTE_BARE_PRINTS_USAGE`. Neovim's exit status is not a verdict: with this config it stays 0 even after `cquit 1`. The shell gate below decides.

Run A, clean room. Every XDG directory except config points into a fresh temporary root:

```sh
room=$(mktemp -d)
printf 'puts "hello"\n' > "$room/sample.rb"
env XDG_CONFIG_HOME=<worktree>/neovim/.config \
  XDG_DATA_HOME="$room/data" XDG_STATE_HOME="$room/state" XDG_CACHE_HOME="$room/cache" \
  PROBE_OUT="$room/probe.out" PROBE_FILE="$room/sample.rb" \
  nvim --headless "+luafile <scratchpad>/probe.lua"
cat "$room/probe.out"
grep -qx 'RESULT pass' "$room/probe.out"
```

Run B, Etienne's real data: the same command without the `XDG_DATA_HOME`, `XDG_STATE_HOME` and `XDG_CACHE_HOME` overrides. Keep `PROBE_OUT` and `PROBE_FILE` in a temporary directory.

`XDG_CONFIG_HOME=<worktree>/neovim/.config` makes `stdpath("config")` the worktree's config, so lazy.nvim reads this branch's specs and writes this branch's `lazy-lock.json`. The live config in the main checkout stays untouched.

### ACP cleanup

`;aa` starts avante's ACP provider, `npm exec @zed-industries/claude-code-acp`, and that process outlives `qa!`. Before each probe run, save `pgrep -f claude-code-acp`. After the run, stop only the PIDs that were not in that list. Never stop a process that was running before the probe; Etienne may have his own avante session open.

## Risks

- The temporary root must be short. Neovim's byte-code cache names each file after the full path of its Lua module. Under the long Claude scratchpad path, the names pass the 255-byte limit, and startup shows false `ENAMETOOLONG` errors. A `mktemp -d` root under macOS `$TMPDIR` works. Do not put the probe's XDG directories in the scratchpad; the `probe.lua` file itself may live there.
- Run B changes Etienne's real plugin directory. It installs the two mega plugins and moves every plugin to its newest commit. A normal launch does the same update. Until this branch merges, the live config lists the two plugins as unused in `:Lazy`; that is not an error.
- The `XDG_CONFIG_HOME` override also hides `~/.config/git/config` from the git processes that lazy.nvim starts. Plugin clones use public HTTPS, so they need nothing from that file.
- Etienne's main checkout has an uncommitted `neovim/.config/nvim/lazy-lock.json` (auto-update drift). `git pull` on `main` after the merge refuses to overwrite it. The pull request body must name this conflict and leave the choice to Etienne: inspect the drift, then keep it (a named stash or a commit elsewhere) or discard it. The implementer never touches the main checkout.
- avante can add another hard dependency in a later commit, and auto-update then breaks startup again. This branch does not prevent that: auto-update stays, per the intent.
- `mega.cmdparse` requires `mega.logging >= 1.1.1, < 2.0` in its rockspec. lazy.nvim does not read that file (it is named `template.rockspec`), and a future `mega.logging` 2.0 on `main` could break `mega.cmdparse`. Auto-update accepts that risk.
- The probe's `;aa` check runs avante's ask with the `claude-code` ACP provider. It opens the sidebar and starts the ACP process, but it sends no prompt.

Rejected:

- Pin avante to `aa05b85`, the commit before the new dependency. It conflicts with the auto-update choice, and the intent asks for avante to load with its new plugins.
- A separate spec file for the mega plugins. They exist only for avante; a separate file hides why they are there.
- Let lazy.nvim install `mega.cmdparse` as a luarocks rock. It needs luarocks, a system tool the intent does not approve.
- A committed headless Neovim test in `test/`. CI has no Neovim, a workflow change needs approval, and a skipped test is not allowed.
