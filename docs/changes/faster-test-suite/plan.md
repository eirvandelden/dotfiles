# Plan: Faster test suite

From `intent.md` (2026-10-19). Status: accepted.

## Design decisions

- The runner is `bin/test`, a Ruby script with only the standard library (`etc`, `rbconfig`, `tempfile`). `bin/` is not in `packages.conf`'s `STOW` list, so stow never links it into `$HOME`. `bin/generate-codex-agents` already lives there.
- `bin/test` with no arguments runs `test/*_test.rb` from the repository root. With file arguments it runs only those files. This keeps it testable with fixture files and gives a quick way to rerun a few files.
- Each file runs as `RbConfig.ruby -Itest test/<file>_test.rb`, with the repository root as working directory, through `Process.spawn(..., pgroup: true)`. That is the exact standalone command, so a green full run also proves every file runs on its own. Each file has its own process group, so a group kill inside one file can never reach another file or the runner. The root is the parent of `bin/test`'s own directory, so a copy of `bin/test` in a fixture root discovers that root's files.
- Concurrency defaults to `Etc.nprocessors`. `-j N` overrides it. Each file's combined stdout and stderr goes to its own temporary file. The runner prints that output in one block, headed `=== <file> (<seconds>s) ===`, when the file ends, so the outputs of parallel files do not mix.
- Files start in alphabetical order. No timing cache is kept: it adds state for a small gain. The per-file seconds in each header show which files are slow.
- The runner ends with a summary: the number of files run, and one `FAILED: <file>` line per failing file. It exits 1 when any file fails and 0 when all pass. On INT or TERM it sends KILL to every running child's group, then exits 130.
- `stop_hanging_stubs` in `test/worktree_sweep_test.rb` stops sending signals to numeric groups. Today it sends KILL to every group id the stubs recorded, and the current comment already admits those ids "may belong to new processes by now". Instead, the hanging stubs wait on a release file instead of a plain `sleep 600`: the `gh` stub loops `sleep 0.2` until `<enclosing>/release-hanging-stubs` exists (600 s at most), and the `hanging-ssh` stub runs the same loop in `sh`. `stop_hanging_stubs` creates the release file, and each live stub exits by itself. A stub that is already dead receives nothing, and no process outside the stubs can receive a signal from the cleanup. When `hanging-ssh` exits, `git fetch` fails and exits. A new `hanging-ssh` started after release sees the file and exits at once. The `hanging-groups` file and its `HANGING_GROUPS` variable go away.
- Before that fix, the implementer reproduces the reported failure once: six files at a time in one shared process group, with `stop_hanging_stubs` logging each recorded group and each kill target. The finding goes in the implement report. The fix does not depend on the finding, because it removes every numeric group kill from the cleanup.
- `LefthookBinary.locate` keeps its order of `LEFTHOOK_BIN`, then `PATH`, then the rv glob. The change is in the `PATH` step: when `which lefthook` finds a RubyGems wrapper script, it asks RubyGems in the test process which gem the wrapper would run: `Gem::Specification.find_by_name("lefthook").full_gem_path`, then `libexec/lefthook-<os>-<cpu>/lefthook` under it. This matches the wrapper's own choice across all gem homes on `GEM_PATH`. On this Mac the wrapper sits in `rv/gems/ruby/4.0.0/bin`, whose newest lefthook is 2.1.2, but RubyGems runs 2.2.2 from the Ruby's own gem directory; a "wrapper's own gem home" rule would silently downgrade. The test process and the wrapper both run the `ruby` on `PATH`. When the gem is missing (`Gem::MissingSpecError`) or has no native binary for the platform, it returns the wrapper, as today. A RubyGems wrapper is a file that starts with `#!` and contains `This file was generated by RubyGems`. A native binary (CI's `/usr/local/bin/lefthook`) is returned unchanged.
- `<os>` comes from `RbConfig::CONFIG["host_os"]` (`darwin`, `linux`). `<cpu>` comes from `RbConfig::CONFIG["host_cpu"]`: `arm64` and `aarch64` map to `arm64`, `x86_64` maps to `x64`. These are the names the gem's `libexec` directories use.
- `test/isolated_git_test.rb` stops running `test/review_report_check_test.rb`. In its place it uses two minimal Minitest fixture files in a temporary directory, each with one test method that commits twice on `main` in a temporary repository. The positive fixture has `require_relative "isolated_git"`, the same line every test file has, and `test/isolated_git.rb` is copied beside it so that line loads the real helper. The negative fixture is the same file without that line. Under the hostile hook config the positive fixture must pass and the negative fixture must fail with `global hook refused main`. This keeps the guarantee (a test file that requires the helper survives the global no-push-to-main hook) and its negative counterpart, at a fraction of a second. `test_every_test_file_requires_the_helper` stays the check that every real test file has the line.
- The `gh` and `herdr` stubs in `test/delivery_harness.rb` change only their shebang, to `#!/usr/bin/env -S ruby --disable-gems`. They use `fileutils` and `json`, which load from Ruby's own library directory without RubyGems. `env -S` exists on macOS and on GNU coreutils 8.30 and later (ubuntu-latest).

## Files that change

- `bin/test` — new. The parallel runner described above.
- `test/test_runner_test.rb` — new. Tests for `bin/test` with fixture test files in a temporary directory.
- `test/worktree_sweep_test.rb` — the hanging stubs wait on a release file; `stop_hanging_stubs` creates that file and sends no signals; `hanging_groups_file` and `HANGING_GROUPS` go away; a new test proves a bystander in the stub's own process group survives.
- `test/lefthook_binary.rb` — the `PATH` step resolves a RubyGems wrapper to the native binary of the gem RubyGems would run. `locate` and the new helpers take the `PATH` lookup result, the gem path lookup and the platform as injectable keyword arguments, with today's values as defaults.
- `test/lefthook_binary_test.rb` — new. Tests for `LefthookBinary` with a fake wrapper and fake gem home.
- `test/isolated_git_test.rb` — the child run of `review_report_check_test.rb` is replaced by a minimal test file fixture, with a positive and a negative test.
- `test/delivery_harness.rb` — the stub shebang gains `--disable-gems`; the header comment says why.
- `test/delivery_harness_test.rb` — new. Proves a stub call starts without RubyGems.
- `.github/workflows/dotfiles-tests.yml` — the test step calls `bin/test`.

## Risks

- A test that writes shared state (a fixed path in `/tmp`, a fixed port, the real `$HOME`) can fail only when run beside another file. Step 8 finds these. Fixing one is in scope only when the test keeps checking the same behaviour.
- `-j` equal to the core count may not be the fastest under Defender, because most time is process start-up wait. Step 9 measures it before any default changes.
- CI's ubuntu-latest has 4 cores. Parallel runs there also expose shared-state bugs. The step 10 push is the check.
- `env -S` needs coreutils 8.30 or later on Linux. ubuntu-latest has it. A very old Linux would fail the stubs loudly, not silently.
- The lefthook gem layout (`libexec/lefthook-<os>-<cpu>/lefthook`) is the gem's own. If a future gem changes it, resolution returns the wrapper, which is today's slower but working behaviour.
- The release-file loop adds one `sleep` process per 0.2 s while a stub hangs. Only the two hang tests use it, for about 3 s each.
- Rejected: checking `Process.getpgid(pid) == pgid` before a group kill. A recycled pid that becomes a group leader passes that check, so it still can kill an unrelated group.
- Rejected: a timing cache to start the slowest files first. It adds state in the repository or `tmp/` for a small gain.
- Rejected: `xargs -P` or GNU `parallel`. The first does not give each file its own process group or keep outputs apart; the second is a new tool.
- Rejected: one Ruby process that loads every test file (Minitest's own parallel executor). Many files change `ENV`, `Dir.chdir` or global constants, and `ruby -Itest test/<file>_test.rb` must keep working as is.
- Rejected: a `#!/bin/sh` wrapper that runs `ruby --disable-gems -x`. It adds a shell start to every stub call; `env -S` does not.

## Critique

### Round 1 (codex exec -p terra)

- The pid-and-pgid check does not remove pid reuse, since a recycled pid that leads a new group passes it, and the regression test used separate groups instead of the reported shared group → fixed (stubs now wait on a release file and the cleanup sends no signals; the regression test puts a bystander in the stub's own group; a reproduction step with kill-target logging comes first)
- Resolving the native binary from the wrapper's own gem home picks lefthook 2.1.2 on this Mac while RubyGems runs 2.2.2 → fixed (resolution asks RubyGems in the test process for the lefthook gem path, via find_by_name and full_gem_path; tests cover a split gem home and a missing gem)
- A temporary fixture cannot load the repository helper with `require_relative`, and one fixture cannot both have and lack the helper → fixed (the positive fixture gets a copy of `test/isolated_git.rb` beside it; a separate negative fixture has no require line)
- The runner tests bypass no-argument discovery, the full-run check trusts the runner's own count, and the standalone proof covers only three files → fixed (discovery test with a copied `bin/test` in a fixture root; the full-run check compares output headers with `ls test/*_test.rb`; the runner starts every file with the exact standalone command, asserted by a test)
- Step 9 only adopts a faster `-j` default when clearly better, which can leave the 8-minute criterion unmet → fixed (the fastest measured value becomes the default; if none meets 8 minutes, the implementer stops with a `Decision needed:` line)
