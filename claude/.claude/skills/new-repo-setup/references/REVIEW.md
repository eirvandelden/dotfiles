# Review policy

Read by the `reviewer` agent (and the `review` skill's pane backend) alongside
`docs/changes/<slug>/plan.md` and `spec.md` and the diff. Work repos: this file is
`REVIEW.local.md`, stowed from the private repo; the reviewer looks for `REVIEW.md` first,
then `REVIEW.local.md`.

## Passes

Every review runs three passes, in this order:

1. **Bugs.** Logic errors, edge cases, incorrect assumptions, race conditions, off-by-one
   errors — anything that makes the code do the wrong thing.
2. **Security.** Injection, unsafe deserialization, missing authorization checks, secrets in
   code or logs, unsafe external input handling.
3. **Compliance.** The diff matches `plan.md`: every file it named changed the way it said,
   nothing unplanned crept in. Behaviour matches `spec.md`: every acceptance criterion has a
   test in the diff that proves it, or is reported as missing. Every test named in the plan's
   `## Proof` exists. No existing test was weakened, skipped, or deleted. Code follows the
   playbook and this repository's `AGENTS.md`.

## What Important means here

A finding is **Important** when it would cause wrong behaviour, a security hole, or a gap
between what was promised (`spec.md`) and what was built — including any missing or weakened
test the compliance pass turns up. Everything else is a **Nit**.

## Cap the nits

Report at most five nits. Beyond that, name the count only ("12 more nits not listed") rather
than listing them all — the reviewer's job is to be read, not to be exhaustive.

## Do not report

- Generated files (lockfiles, compiled assets, autogenerated schemas).
- Anything a linter or formatter already enforces — trust the pre-push checks for that.
